# Working on this backend

This is the Laravel API of the AlphaMaster platform. It is API-only (ADR 0001) and
custom-modular (ADR 0002): there are no framework routes outside `app/Modules/*/Routes`,
and no controller, model or migration lives outside a module.

Read this before changing anything here. It is short on purpose — the decisions live in
`docs/adr/`, and this file only says where to look, which instructions win, and what the
project will not accept.

## Which instructions win

Two sets of guidance exist in this repository and they are not equal.

1. **`docs/adr/`** — 43 accepted records, indexed in `docs/adr/README.md`. They are the
   authority on why this code is shaped as it is. A change that contradicts one is a
   change to that record, not a change to the code.
2. **`backend/AGENTS.md`** — generated by `php artisan boost:install`. Generic Laravel
   and package guidance: useful, and it knows nothing about this project. Where it and
   an ADR disagree, the ADR wins. It should not be regenerated without reconciling it
   with the records above, which is the work issue #40 describes.

This file used to contain Boost's *pre-install* bootstrap block, telling every agent to
run `composer require laravel/boost --dev` and `php artisan boost:install` before
touching a request. Both had already happened: the package is a dev dependency in
`composer.json` and the generated guidelines are in `backend/AGENTS.md`. The instruction
was therefore stale rather than merely unfollowed, which is why it was correctly ignored
throughout M1 and M2.

## Where the rules are

- **`tests/Feature/ArchitectureTest.php`** — the module boundaries are enforced, not
  merely described. Core does not import a domain module; Media is not imported by the
  modules it serves; the cache facade is reached only through the platform cache.
- **ADR 0031** — every response uses one envelope, and every error carries a stable code
  alongside a localized message. **ADR 0030** — a human label sits beside the identifier
  it describes and never replaces it.
- **ADR 0027** — PostgreSQL is authoritative for test execution; the SQLite run is a
  secondary check, not a substitute.
- **`scripts/gate.sh`** — the quality gate, defined once and run identically by a
  developer and by CI.

## What this project will not accept

- **A gate that has stopped checking.** Several checks here carry positive controls that
  plant a defect and require it to be detected, because this codebase has twice been
  caught by a check reporting clean after it had stopped looking. If you add a check,
  prove it can fail.
- **A baseline instead of a fix.** Static analysis runs at level 5 with no baseline;
  ADR 0029 records the remaining level 8 findings rather than suppressing them.
- **An invented capability.** The Admin renders what the API publishes. If a control
  needs an endpoint that does not exist, the endpoint comes first — or the absence is
  stated in the interface.
- **A secret that can be read back.** Credentials and secret settings are write-only
  through the API; `has_credentials` is a boolean for that reason.
- **A hand-edited contract.** `backend/openapi.json` is generated from the code
  (ADR 0010) and committed. If it is wrong, the code or its annotations are wrong.

## Running things

Everything runs inside the project's own images, so a green result is a statement about
the environment this project actually ships:

```sh
make up                            # start the stack
bash scripts/gate.sh all           # the full gate, as CI runs it
bash scripts/gate.sh test-pgsql    # the suite on the authoritative engine
bash scripts/gate.sh openapi       # regenerate the contract, validate, fail on drift
bash scripts/gate.sh admin         # the Admin UI gate
```
